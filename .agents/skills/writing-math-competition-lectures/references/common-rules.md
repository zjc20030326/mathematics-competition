# 通用讲义规则

## 1. 规则优先级

按以下顺序处理冲突:

1. 用户当前任务的明确要求.
2. 当前本地 `.tex`,`.md`,导言区,文档类和目录结构.
3. 根目录和子项目 `AGENTS.md`.
4. 用户提供的原始 PDF 或其他资料.
5. 已安装的数学,LaTeX 和文档 Skill.
6. 模型知识或外部资料.

当前文件可能包含用户在原始 PDF 之后做出的人工修正. 不得用旧聊天,旧模板或旧输出覆盖当前内容.

当前源码与原始资料不一致时,先报告差异. 只有任务明确要求校勘,或用户确认后,才能改动当前题面和结论.

## 2. 任务范围

局部题目任务只处理题目及其直接依赖. 不顺手重写同章其他解答.

整章任务必须阅读整章,逐题检查并满足本文件的整章完成门.

工程结构任务只修改实现目标所需的共享文件,入口和文档. 不修改无关数学内容.

局部任务发现全章或全书系统性问题时,记录影响并询问是否扩大范围.

## 3. 原始资料和溯源

使用原始 PDF 时记录:

- PDF 文件名.
- 使用的页码或页码范围.
- 当前源码与资料是否一致.
- 尚未核对的范围.

只有歧义必须留在源码中时才加入源码注释. 其他校勘信息写入任务报告或对应问题记录.

不得宣称完成全书校勘,除非实际检查了全部声明范围.

## 4. 英文标点

所有新增或修改的自然语言正文使用英文标点. 修改既有段落时,只统一该段落,不为标点机械改写未触及全文.

映射规则:

- 中文逗号改为 ASCII comma.
- 中文句号改为 ASCII period.
- 中文冒号改为 ASCII colon.
- 中文分号改为 ASCII semicolon.
- 中文问号改为 ASCII question mark.
- 中文感叹号改为 ASCII exclamation mark.
- 中文圆括号改为 ASCII parentheses.
- 中文方括号改为 ASCII square brackets.
- 中文引号改为 ASCII quotation marks.
- 中文顿号按语义改为 ASCII comma 或 Markdown 列表.
- 中文省略号在正文中改为 `...`,在数学中按语义使用 `\ldots` 或 `\cdots`.
- 中文破折号按 LaTeX 语义改为 `--` 或 `---`.

以下内容不做机械替换:

- 数学公式和数学定界符.
- 文件名和真实路径.
- URL.
- 代码和 LaTeX 命令.
- 必须忠实保留的原文引用.
- 具有专门 LaTeX 语义的符号.

## 5. 方法选择

解答方法按以下优先级选择:

1. 优先使用例题所在 `subsection` 或 `methodsection` 正在讲授的方法.
2. 当前方法不适用或明显不自然时,使用同一 `section` 之前已经讲过的方法.
3. 仍不适合时,使用课程范围内的其他方法,并简要说明原因.
4. 不为形式统一强行使用更长,更绕或不完整的方法.
5. 默认保留一个最适合教学位置的解答. 只有用户要求时才增加多解.

## 6. 证明完整性

以学生能够独立复现证明为标准.

必须写出:

- 关键恒等式.
- 所用定理的假设及其验证.
- 重要不等式的来源.
- 参数,指标,定义域和符号范围.
- 极限交换,传递或估计成立的依据.
- 每一问的明确结论.

不得用"显然","易知"或"不难得到"代替关键步骤. 可以合并纯机械计算,但计算本身是核心方法时必须展开.

引用前文不能代替当前证明的关键桥梁.

## 7. 符号纪律

- 优先复用题面和正文已有符号.
- 新符号必须立即定义并说明用途.
- 只在揭示结构,缩短后续多步推导或重复使用时引入符号.
- 删除只使用一次且不改善结构的别名.
- 不重复定义同一对象.
- 不为减少符号而省略必要推理.

完成整章检查时,额外检查辅助符号是否必要.

## 8. 同书关联

前文定理,命题或例题直接支持当前解答时:

- 写出准确编号.
- 说明假设和符号如何对应.
- 写出当前题仍需完成的关键推导.

有教学价值时,简要说明当前题是前题的推广,特例,逆命题,反例或后续应用.

当前统一使用正文编号描述,不主动新增 `\label` 和 `\ref`. 章节重排后必须复核这些文字编号.

## 9. 疑问题面

不得静默修正疑问题面.

按当前题面给出以下一种或多种处理:

- 反例.
- 缺失条件分析.
- 分类讨论.
- 按字面能够得到的结论.

明确说明需要核对的内容. 在该书的 `解答问题记录.md` 中记录:

- 题号.
- 问题类型.
- 当前解答如何处理.
- 原始 PDF 名称和页码.
- 待确认,已确认或已修正状态.

只在发现第一个问题时创建记录文件,不创建空记录. 用户确认修正后,同步更新共享源码和问题记录.

## 10. 普通版和答案版

一本书是否需要普通版和答案版,以及如何实现,由书籍专属规则决定.

`数学分析培优` 必须维护两种输出. 未来的高等代数培优讲义也需要普通版和答案版,但在实际文件出现前不得预设项目名,章节,目录,留白和分页结构.

其他未来讲义先读取当前文件并向用户确认,不得自动复制数学分析结构.

## 11. 并发修改和 Git 安全

- 工作前检查 Git 状态.
- 修改前重新读取目标文件.
- 保留所有无关修改和未跟踪文件.
- 完成前再次检查目标文件和 Git 状态.
- 非重叠修改只做窄范围合并.
- 目标区域发生重叠修改时必须停止并询问,不得根据猜测覆盖.
- 不使用破坏性 reset 或 checkout.
- 未经明确要求不创建分支,提交,推送或 pull request.

## 12. 整章完成门

只有同时满足以下条件才称整章完成:

- 已阅读全章源码和标题结构.
- 每个例题都有完整解答.
- 没有未解释的待办标记或空解答.
- 解答遵循本节方法优先级.
- 已检查符号必要性和一致性.
- 有价值的同书关联已记录.
- 疑问题面已写入问题记录.
- 修改正文通过英文标点检查.
- 普通版和答案版结构检查通过.
- 两个单章入口均编译.
- 两个整书入口均编译.
- 日志已检查.
- 版式敏感页面已目视检查.

任一条件未满足时,报告剩余项,不得把框架或部分答案称为完成.

## 13. 固定完成报告

最终报告包含:

- 修改文件.
- 数学,结构和版式变化.
- 重要方法选择.
- 新增,解决和遗留的资料问题.
- 静态检查结果.
- 实际编译目标和 PDF 页数.
- 剩余 warning 及其是否为新增.
- 实际目视检查的 PDF 和页码.
- 未验证范围.
- 剩余工作和下一步.
- 修改文件的绝对可点击链接.

报告必须区分源码检查,真实编译和 PDF 目视检查. 不得用其中一种代替另外两种.
